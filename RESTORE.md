# Полное восстановление проекта в другом Codex

## 1. Клонирование

Репозиторий должен оставаться приватным: в диалогах и материалах есть рабочий контекст.

```bash
git clone https://github.com/OLYMARKES/mybotica-codex-workspace.git mybotica-codex-workspace
cd mybotica-codex-workspace
git lfs install
git lfs pull
./tools/bootstrap.sh
```

## 2. Открытие в Codex

1. Откройте корневую папку репозитория как локальный проект Codex.
2. Подтвердите доверие репозиторию — иначе проектный `.codex/config.toml` не загрузится.
3. Создайте новую задачу из корня, не из случайной вложенной папки.
4. Передайте агенту стартовый промпт из `README.md`.
5. Для продолжения конкретной ветки работы укажите соответствующий файл из `codex-history/transcripts/`.

Codex автоматически увидит скиллы в `.agents/skills/`; копировать их в домашнюю папку не требуется.

## 3. Модель и стиль

В `.codex/config.toml` зафиксированы исходные значения:

- модель: `gpt-5.6-sol`;
- reasoning effort: `high`;
- personality: `pragmatic`;
- sandbox: `workspace-write`;
- approvals: `on-request`.

Если эта модель недоступна в другом аккаунте, точного воспроизведения поведения не будет. Используйте ближайшую доступную модель только после явного решения владельца проекта.

## 4. Плагины и программы

Проверьте и при необходимости установите в Codex:

- Browser (встроенный браузер);
- Computer Use;
- Image generation;
- PDF;
- Visualize;
- GitHub (не обязателен для локальной работы, нужен для операций с GitHub из Codex).

Для видео нужны Node.js/npm, FFmpeg и Git LFS. HyperFrames вызывается через зафиксированные команды в `videos/*/package.json` и вложенные `AGENTS.md`.

Higgsfield использует собственный CLI/сервис и требует отдельной авторизации. Подключения Telegram, GitHub, Higgsfield и любых OAuth-сервисов нужно выполнить заново на новом компьютере.

Никогда не переносите через Git:

- `~/.codex/auth.json`;
- `~/.codex/secrets/`;
- браузерные профили и cookies;
- Telegram session-файлы;
- `.env` и токены;
- внутренние SQLite-базы Codex.

## 5. История диалогов

`codex-history/transcripts/` содержит читаемые реплики пользователя и агента. `codex-history/threads/` содержит полный переносимый журнал событий: команды, инструменты, результаты, изменения файлов и связи сабагентов.

Это архив и контекст для нового агента, но не официальный формат импорта задач Codex. На момент создания снимка официальный импорт Codex ориентирован на Claude/Cursor; гарантированного импорта собственных Codex-задач из Git нет. Поэтому новый агент должен читать нужный транскрипт и продолжать работу в новой задаче.

## 6. Проверка

```bash
./tools/verify_clone.sh
./tools/secret_scan.sh
```

Если проверка сообщает об отсутствующем Git LFS-файле, выполните `git lfs pull`. Если не хватает плагина или авторизации, установите/подключите его в интерфейсе Codex и начните новую задачу, чтобы инструменты появились.
